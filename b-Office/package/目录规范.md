# WBall 项目目录规范

## 根目录规则

根目录可以直接保存少量全项目入口文件，例如 `README.md`、解决方案依赖配置和仓库配置。新增可见文件夹应使用以下三个级别：

| 前缀 | 含义 | WBall 内容 | 示例 |
| --- | --- | --- | --- |
| `a-*` | 分项目或子项目 | 具有独立目标、边界和交付物的子项目 | 当前未使用 |
| `b-*` | 当前项目的组成部分 | 源码、验证、文档、素材和发布工作区 | `b-Code-WBall/`、`b-Office/` |
| `z-*` | 供其他项目或部署流程消费的元目录 | 稳定包、消费合同或正式快照 | `z-Package/` |

以 `.` 开头的 Git、IDE 和系统状态目录属于工具基础设施，不作为项目级目录，并应由 `.gitignore` 管理。

仓库现有 `Unused/` 是建立本规范前遗留的冻结素材区，只作为历史兼容例外；不得继续向其中加入活动源码或现行文档。后续确需治理时必须单独立项，不在普通功能修改中顺手搬迁。

## b 级现行目录

| 目录 | 所有权与职责 | 生成物边界 |
| --- | --- | --- |
| `b-Code-WBall/` | 产品 Core、Application、App 与解决方案 | `bin/obj` 可重建，不入库 |
| `b-Code-Verify/` | Fast、Full 与专项验证器 | 验证临时 artifact 不入库 |
| `b-Office/` | 现行合同、复用规则和冻结历史 | `current/package` 是活动真值，`history` 默认不读取 |
| `b-Picture/` | 图片素材 | 大型二进制按 Git/LFS 规则管理 |
| `b-Video/` | 视频素材 | 大型二进制按 Git/LFS 规则管理 |
| `b-Publish/` | 单槽开发测试候选与发布事务工作区 | 只跟踪 `README.md`；candidate/history/work/quarantine 产物不入库 |
| `z-Package/` | 最新正式可消费 WBall 快照 | 只由发布脚本原子提升；二进制、manifest 和 checksum 纳入 Git/LFS |

## a 级：子项目

- 只在某部分具备独立目标、生命周期或交付物时建立 `a-*`。
- 名称表达子项目身份，不使用 `a-Temp`、`a-New` 等临时名称。
- 临时任务、草稿和单个功能不能为了分类方便升级成 a 级。

## b 级：项目组成

- b 级内容由 WBall 拥有，随当前项目开发和交付。
- 按职责命名，例如 `b-Code-<组件>`、`b-Office`、`b-Picture`、`b-Publish`。
- 可重建生成物不得与权威源混放；运行时用户数据统一位于 `%AppData%/WBall/`。

## z 级：跨项目复用元目录

- 只有已经形成稳定消费合同、确实供其他项目或部署流程使用的内容才能进入 `z-*`。
- z 级不是普通构建输出或源码备份；消费者、版本、兼容性和权威来源必须明确。
- `z-Package/` 只保存最近一次通过 Release、Fast、Full、manifest/checksum 复验的正式版本；不能手工复制生成。
- WBall 当前是 AppShell 消费者，不在本仓复制 `2026-023-AppShell` 的包或文档。

## 新目录决策

1. 能否直接作为全项目入口文件保存？能则不创建目录。
2. 是否是具有独立目标和交付物的子项目？是则使用 `a-*`。
3. 是否由 WBall 拥有并参与当前项目开发？是则使用 `b-*`。
4. 是否已有稳定合同并供其他项目消费？是则使用 `z-*`。
5. 以上均不满足时，不应进入仓库根目录。
