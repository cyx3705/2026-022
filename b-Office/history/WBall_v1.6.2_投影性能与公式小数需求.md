## 0. 一句话定义

**v1.6.2** 专注两件事：

1. **性能**：削减仿真热路径上「成绩 / 球属性 → SQLite 投影」的过量写入，并顺带砍掉其它已证实或高嫌疑的卡顿源；  
2. **公式区小数**：小球窗公式参数（及约定下的预览/换算）**明确支持小数**，不再被「取整」语义误伤到输入侧。

玩法（`Xn` / `RUN` / 裁判 / 开局）语义不变。

## 1. 问题陈述（v1.6.1 之后为何仍卡）

| 现象 | 初步根因（产品/架构层） |
|---|---|
| 多球 + 频繁进销毁器时卡顿 | 每次性质变化触发 `SceneWorld.Changed` → `PropertyProjection` **防抖后全表 DELETE + 逐行 INSERT**（balls / objects / wireframes / solids / **factions 含 score**） |
| 猜「成绩和小球信息写库」 | **成立倾向高**：`Xn`/`RUN` 改 multiplier、size、weight、阵营 score 后都会走同一条全量投影；表窗口若打开还会被 `DataChanged` 连带刷新 |
| 1.6.1 取整后仍差 | 取整只减轻物理浮点细量，**未切断写库路径**；渲染侧仍有每帧分配（标号 `FormattedText`、尾迹 `ToArray`、大量临时 Brush/Pen） |
| 公式想调 0.5 等 | 产品要求公式区支持小数；需与「结果是否仍取整」划清边界，避免再把输入当成整数 |

### 1.1 当前写库链路（现状快照）

```
仿真 Tick
  └─ PhysicsEngine.TeleportBall（Xn / RUN 等）
       └─ NotifyChanged(project: true)   // 性质变化时
            └─ SceneWorld.Changed
                 ├─ DropZone / 裁判窗 / 小球窗 / 对象调试 → UI 刷新
                 └─ PropertyProjection 防抖 ~150ms
                      └─ SyncFromWorld()
                           DELETE balls + 全量 INSERT
                           DELETE scene_objects + 全量 INSERT
                           DELETE wireframes / solids / factions + 全量 INSERT
                           （含 score）
```

补充：

- 普通位移帧**不**走这条链路（仅 `InvalidateVisual`），卡顿高峰更可能集中在 **传送/计分密集段** 与 **全量同步撞上表窗口刷新**。  
- `NotifyChanged` 的 `project` 参数现状是「为 false 则整事件不触发」，**不能**做到「只刷新画布、不同步库」；热路径控制力不足。  
- `SyncFromWorld` 多为逐条 `ExecuteSql`，未见单事务打包；球/对象稍多时同步本身就重。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G1 | **仿真热路径默认不再全量写 SQLite**；成绩与球结果以 `SceneWorld` 为准，投影按策略延迟/节流/增量 |
| G2 | `Xn`/`RUN` 高频发生时，体感卡顿相对 1.6.1 **明显改善**（主观可玩；条件允许则加简易帧时对比） |
| G3 | 表窗口仍可查看 balls / factions，但**不是**实时权威引擎；允许短暂滞后 |
| G4 | 小球公式区：**Base/Scale/初始标号等输入与落盘支持小数**（见 §5.2） |
| G5 | 版本号 **1.6.2**；不改冻结区（除非事务 API 等确需上报） |
| G6 | 顺带完成 1～2 项**低风险渲染/事件**优化（见 §5.3），避免只改库仍卡在绘制 |

### 2.2 非目标

- 不改 `Xn` / `RUN` / 裁判积分规则本身  
- 不做第三方物理引擎、不做 GPU 渲染重构  
- 不把公式重新塞回表窗口  
- 不强制场景 JSON 嵌入公式（仍全局 `ball_formula.json`）  
- 不以「取消取整」作为性能主方案（小数输入 ≠ 必须恢复高精浮点热路径）

## 3. 与前版关系

```
v1.6.1
  · 公式入口纠正 + size/weight 取整
        │
        │  v1.6.2
        ▼
v1.6.2
  · 投影写库与热路径解耦（主）
  · 公式区小数（明确）
  · 可选渲染/事件小优化
```

| v1.6.1 | v1.6.2 |
|---|---|
| 取整减轻物理细量 | **切断/节流写库**才是本版性能主轴 |
| 公式参数已是 double，但产品未强调小数 | **UI/语义/验收**明确支持小数 |
| `project` 形参无力细控 | 拆分「UI 脏」与「投影脏」或等价机制 |

## 4. 术语

| 术语 | 含义 |
|---|---|
| **投影** | SQLite 中 balls / factions 等镜像表，供表窗口查看，**非**运行时权威 |
| **热路径** | 仿真播放中每帧物理、以及销毁器传送/计分 |
| **全量同步** | `SyncFromWorld`：删光再插全表 |
| **投影脏** | 内存相对投影表有未刷结果（倍率、size、weight、score 等） |
| **公式参数小数** | SizeBase/Scale、WeightBase/Scale 等可为非整数（如 `0.5`） |
| **结果量化** | 公式算出后写入球的 size/weight 粒度（整数或有限小数位） |

## 5. 功能与性能需求

### 5.1 投影写库策略（P0）

| 编号 | 需求 | 优先级 |
|---|---|---|
| PERF-01 | 播放中（`IsPlaying`）**禁止**因球位移、传送闪光、尾迹等触发全量 `SyncFromWorld` | P0 |
| PERF-02 | `Xn`/`RUN` 导致的 multiplier / size / weight / faction.score 变化：默认 **不立即写库**；仅标脏 | P0 |
| PERF-03 | 投影刷新触发点建议（可组合）：暂停仿真、手动 `ball.recalc`/保存场景、表窗口显式刷新、防抖间隔加大（如 ≥500ms～1s 且仅脏时）、退出播放 | P0 |
| PERF-04 | 若保留定时投影：应用**单事务**包住一轮 DELETE/INSERT；禁止无事务逐条提交（若冻结区 API 不够则上报或在 App 侧批 SQL） | P0 |
| PERF-05 | **优先增量**：至少 factions（score）与变更球行可 UPDATE；全量重建降为冷路径（加载/大改结构后） | P1（强烈建议本版做完至少「脏表级」而非永远五表全删） |
| PERF-06 | 拆分事件：`VisualChanged`（画布）与 `ProjectionDirty`（库）或给 `NotifyChanged` 增加独立 flags；传送位置变化须能刷新画布而**不**刷库 | P0 |
| PERF-07 | 表窗口打开时，不得因每 16ms 物理帧刷库；允许成绩显示短暂落后于裁判窗（裁判窗读内存） | P0 |
| PERF-08 | 文档/控制台注明：投影滞后是预期；权威在 `SceneWorld` | P1 |

**验收直觉**：连续 `Xn` 刷标号时，磁盘/CPU 不再跟着重写整库；裁判区分数仍即时（内存）。

### 5.2 公式区小数（P0）

| 编号 | 需求 | 优先级 |
|---|---|---|
| DEC-01 | 公式区 SizeBase / SizeScale / WeightBase / WeightScale **可输入、解析、保存小数**（InvariantCulture，如 `0.5`、`1.25`） | P0 |
| DEC-02 | 预览区按当前参数用小数参与计算；展示结果按「结果量化」规则显示 | P0 |
| DEC-03 | `formula.set` / `ball_formula.json` 与窗体同一套小数语义 | P0 |
| DEC-04 | 初始标号仍为整数 ≥1（与 K/M/G/T 一致） | P0 |
| DEC-05 | **结果量化（待 §8 确认）**：默认建议见下 | P0 |

**默认建议（写入 §8 待勾选）：**

- 公式 **参数**：小数。  
- **size**：仍量化为整数半径（性能/像素对齐），`Round` 后 ≥2。  
- **weight**：允许 **1 位小数** 或继续整数 ≥1——见 V62Q2。  

> 说明：若 weight 恢复过多小数位，需避免再次拖垮碰撞热路径；「有限小数」优于任意 double。

### 5.3 其它性能候选（本版可挑做）

按性价比排序，**不要求一次全做**；实现阶段选通过验证的项勾进交付。

| 编号 | 项 | 说明 | 建议 |
|---|---|---|---|
| OPT-A | 标号文字缓存 | 每球每帧 `new FormattedText` ×2 → 按 `(label, fontSize)` 缓存或倍率未变时复用 | P0/P1 |
| OPT-B | 尾迹绘制 | 去掉每帧 `Trail.ToArray()`；复用 Pen/减少临时 Brush | P1 |
| OPT-C | 颜色/Brush 缓存 | `ParseColor` + `SolidColorBrush` 按 hex 缓存并 Freeze | P1 |
| OPT-D | 面板刷新节流 | 裁判窗/小球窗/对象调试对 `Changed` 防抖或「仅选中相关才刷」 | P1 |
| OPT-E | 球-球碰撞 | 多球时 O(n²)；网格/休眠球等属 P2，本版仅评估 | P2 |
| OPT-F | 尾迹默认关或缩短 | 产品可调默认 `TrailLength` / 默认关闭 | P1 可选 |

| 项 | 说明 |
|---|---|
| `formula.set` / `formula.show` | 继续；参数小数；show 可带预览样例 |

## 7. UI / 行为草图

```
播放中:
  物理 / 传送 / 计分  →  只改内存 + 画布
  表窗口 balls/factions  →  可滞后或暂停后刷新

暂停 / 保存 / proj.sync:
  → 投影与内存对齐（成绩、倍率、size、weight）

小球窗公式区:
  SizeBase [ 6.5 ]  SizeScale [ 0.75 ]   ← 小数 OK
  WeightBase [ 0.5 ] WeightScale [ 0.5 ]
  预览 标号=10 → size=… weight=…
```

## 10. 验收标准（v1.6.2）

1. 播放中密集 `Xn`/`RUN`：**无明显**「每传送一次卡一下」的写库感。  
2. 暂停或手动同步后，表窗口 `balls.multiplier/size/weight` 与 `factions.score` 与内存一致。  
3. 裁判区分数仍跟手（读内存）。  
4. 公式区可输入并保存小数参数；重启后仍在。  
5. `Xn` / `RUN` / `game.start` / 场景存读回归通过。  
6. 版本号 **1.6.2**。  
7. （若做了 OPT-A）同球数下绘制帧时有改善或分配明显减少。

## 11. 风险

| 风险 | 应对 |
|---|---|
| 表窗口用户以为「没计分」 | 文案：投影可滞后；看裁判区 |
| 崩溃时投影落后 | 场景权威在 JSON/内存；投影可重建；可选退出时强制 sync |
| 冻结区无事务 API | 上报手册流程，或拼接批处理；不擅自改 Core |
| weight 小数再拖性能 | 限制小数位；碰撞仍用量化后的值 |
| 只停写库但绘制仍卡 | 必须带至少一项 OPT（建议 A） |
