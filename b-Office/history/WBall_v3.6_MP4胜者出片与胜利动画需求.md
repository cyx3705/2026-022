# WBall V3.6 MP4 胜者出片与胜利动画需求

> 文档性质：V3.6 版本需求规格  
> 目标版本：**3.6.0**  
> 文档日期：2026-07-31  
> 前置基线：V3.5.2 友军吸收、无上限护盾与四方护盾占比  
> 当前状态：**已完成**

---

## 1. 版本目标

V3.6 将“出片”收敛为单一工作流：冻结指定场景和种子，在独立世界中持续计算到唯一胜者产生，追加固定胜利动画，最终只交付 MP4。机器生成速度只影响等待时间，不能造成跳帧、现场污染或结果漂移。

本版本不改变 V3.5.2 的友军吸收、碰撞互斥、护盾计价、破盾反弹、AppShell 3.0.3 消费方式和用户数据位置。

## 3. 出片接口

### 3.1 页面

“出片与时间”页面删除以下控件：

- `output / simulation / winner` 模式选择。
- 输出时长、模拟时长和最长输出时长。
- MP4、保留 PNG 和 PNG 降级选择。
- 依赖用户时长的总帧数、百分比和 ETA。

页面保留场景、种子、任务名称、分辨率、FPS、帧队列容量和确定性模拟降速参数。结束条件以只读文本显示为“其他阵营的炮台与全部可战积分被消灭”。进度只显示任务阶段、已生成帧数、视频时间、模拟时间、球数、模拟倍率、生成 FPS 和工作集。

分辨率提供 1280x720、1920x1080、2560x1440、3840x2160 预设和自定义宽高。宽高必须为偶数，合法范围为宽 `320..7680`、高 `240..4320`；非法值整项失败，不修改当前默认配置。

### 3.2 命令

```text
render.start [seed=<int>] [scenario=<name>] [name=<name>]
render.config [w=<even>] [h=<even>] [fps=<int>] [queue=<int>]
              [autoSlow=<bool>] [previewAutoSlow=<bool>]
              [startBalls=<int>] [fullBalls=<int>]
              [minScale=<double>] [manualScale=<double>]
              [quantum=<double>] [hysteresis=<int>]
render.pause
render.resume
render.cancel confirm=true
render.status
render.list [limit=<int>]
```

- `render.start` 固定使用胜者结束条件，不再接受 `mode`、`seconds` 或 `maxOutputSeconds`。
- `render.config` 不再接受 `mp4`、`keeppng` 或 `maxOutputSeconds`。
- `render.estimate` 直接退役，因为胜者产生前无法权威估算总帧数和成片时长。
- 旧参数必须由命令参数校验明确拒绝，不得静默忽略后创建不同语义的任务。
- `record.config/start/stop/status` 在 V3.6 继续作为兼容别名转发到对应的 winner-only `render.*` 操作，但不得重新暴露旧时长或 PNG 语义；回显继续提示迁移到 `render.*`。

旧 `render_time.json` 中的模式、时长、MP4/PNG 字段在加载时忽略，在下次成功保存配置时自然移除；不得删除用户已有任务目录、manifest、PNG 或 MP4。

## 4. 胜负与淘汰

### 4.1 权威可战价值

新增单一的阵营剩余可战价值查询，必须覆盖：

1. 落球区中颜色归属该阵营的经济球倍率。
2. `SmallAmmo` 小球弹药池。
3. 炮弹队列及其 `QueuedAmmoValue`。
4. 战场中该阵营所有小球、大球和余烬弹体的当前积分。
5. 弹体尚未结算的友军吸收携带值或待吸收值。

上述各项使用饱和加法，不能因整数溢出变负。账面 `Score`、`Points` 可进入诊断快照，但不能代替真实积分载体，因为炮台死亡时它们会被清零。

### 4.2 淘汰与胜者

- 阵营只有在炮台已死亡且剩余可战价值为 0 时才淘汰。
- 炮台死亡但仍有库存、同色经济球或余烬时，该阵营继续参战并允许反杀。
- 每个固定步按现有确定顺序完成伤害、护盾、吸收、死亡爆发和弹体回收后，再统一检查淘汰状态。
- 只剩一个未淘汰阵营时立即锁定胜者、停止自动开火和物理推进；胜者锁定后不得被尾帧事件反转。
- 少于两个有效参赛阵营、开局即无可形成唯一胜者的有效对手时，`render.start` 必须失败，不创建编码任务。
- `HardTimeLimitSeconds` 不得在出片中按领地或生命排名制造胜者；到时限仍未淘汰的战局继续计算。

## 5. MP4-only 流水线

```text
冻结任务输入
  -> 独立世界固定步模拟
  -> 不可变 RenderFrameData
  -> 有界帧队列
  -> 专用 STA 组合 BGRA 帧
  -> FFmpeg stdin 流式 H.264 编码
  -> output.partial.mp4 原子改名为 output.mp4
```

- 随应用发布固定版本的 Windows x64 FFmpeg；正式候选必须登记来源、版本、许可证和 SHA-256。
- BGRA 帧直接写入 FFmpeg 标准输入，不生成中间 PNG，也不把整片原始帧保存在内存。
- FFmpeg 必须以参数数组启动，不通过 shell 拼接任务名称或路径；标准错误异步排空并保留有界诊断尾部。
- 只有 FFmpeg 正常结束、退出码为 0、最终文件存在且容器探测通过，才允许把 `.partial.mp4` 原子改名为 `output.mp4` 并标记完成。
- 编码器缺失、启动失败、管道中断、磁盘写满、非零退出码或容器不可读均标记任务失败，删除无效 partial，保留 manifest，不生成 PNG 兜底。
- 取消任务时关闭生产者和编码输入，终止本任务编码器进程，删除 partial，并写入 `canceled` manifest；不得影响现场或其它进程。

## 6. 胜利动画

胜者锁定后冻结最终战场并固定输出 `3 x FPS` 帧：

1. `0.0..0.5s`：非胜方与背景平滑压暗，胜方保持原色。
2. `0.5..1.5s`：胜方炮台和领地轮廓依次高亮，外圈脉冲一次。
3. `1.0..2.5s`：画面中央显示胜方名称和“胜利”，从轻微放大过渡到稳定尺寸。
4. `2.5..3.0s`：保持最终构图，给播放器和剪辑保留完整尾帧。

动画进度由固定帧号计算，不读取墙钟时间。实时舞台和离线 `StageFrameRenderer` 共用同一胜利展示数据；文本、颜色、胜者 ID 和关键动画进度必须一致。动画结束后才关闭编码输入并封装 MP4。

## 7. Manifest 与安全门限

manifest 至少记录：任务 ID、应用版本、场景与种子、输入哈希、分辨率、FPS、FFmpeg 版本和哈希、胜者 ID/名称、胜者锁定模拟时间、动画起止帧、总帧数、输出/模拟/墙钟时间、最终导演哈希、MP4 路径/大小以及取消或失败原因。

旧的模式、请求时长、最大输出时长、截断成功、PNG 目录和“MP4 失败后 PNG 完成”字段退出当前契约。

用户不可设置时长。任务视频时间达到内部常量 24 小时仍未产生胜者时，以“战局未收敛”失败；该门限只防止失控任务，不得选取领地、生命或积分领先者作为伪胜者。

## 8. 验证与验收

1. 炮台死亡但存在经济球、弹药库存或余烬时阵营仍未淘汰；最后一份价值消失后唯一胜者立即锁定。
2. 胜者锁定后不再推进物理，结果不会被同帧残余事件反转。
3. 720p、1080p、1440p、4K 和合法自定义偶数尺寸生成的 MP4 可被容器探测器读取，编码为 H.264，分辨率和 FPS 与请求一致。
4. 判胜后恰好追加 `3 x FPS` 帧；胜方名称、颜色、炮台和领地高亮正确，实时与离线关键帧一致。
5. 页面和命令中不存在模式、时长、最长输出、PNG/MP4 选择和时长估算入口；旧参数失败且不创建任务。
6. FFmpeg 缺失、启动失败、写入失败、磁盘不足、取消和 24 小时不收敛均进入正确终态，不留下成功 MP4 或 PNG。
7. 出片前后现场配置、状态和确定性哈希不变；暂停和继续不重置时间轴、编码器或胜利动画进度。
8. Fast、Full、出片 smoke、页面 smoke、Release 构建和测试候选通过；V3.1、V3.2、V3.5.2 冻结哈希保持不变，若实现确实改变公共玩法语义则必须显式登记新基线和原因。

## 9. 版本边界与完成定义

- 不修改 AppShell 3.0.3 源码或开启 WBall MCP。
- 不迁移场景格式、用户布局、数据目录或已有录制结果。
- 不恢复实时抓屏，不引入全片 BGRA 缓存。
- V3.6 实施前不得把程序集、项目概览或验证结果标记为 3.6.0 已完成。

只有 winner-only 接口、可战价值判定、3 秒胜利动画、MP4-only 编码、故障事务和全部门禁同时通过，才能把状态改为“已完成”并进入 V3.6 收口。

## 10. 实施结果（2026-08-01）

- 实时舞台与离线组合器共用 `VictoryAnimationState`；离线视频在判胜后严格追加 `3 x FPS` 帧。
- 已随应用固定发布 `ffmpeg version 8.0.1-essentials_build-www.gyan.dev`，`ffmpeg.exe` SHA-256 为 `5AF82A0D4FE2B9EAE211B967332EA97EDFC51C6B328CA35B827E73EAC560DC0D`，许可和来源登记在 `App/ThirdParty/ffmpeg/NOTICE.md`。
- `--render-v36` / `--render-smoke` 已通过：720p、1080p、1440p、4K 与自定义 320x240 均生成可读取的 H.264 MP4；成功目录只有 manifest 与 MP4；取消和编码器缺失不产生 PNG、成功 MP4 或残留 partial。
- Release 构建 0 警告、0 错误，Fast 14/14、Full 100/100、页面 smoke 通过；V3.1、V3.2、V3.5.2 seed 42/43 冻结哈希保持不变。
