## 0. 一句话定义

**v2.0** 把 WBall 从「落球编辑器」升级为「**四方炮台对战视频生成器**」:

- **左世界(经济)= 沿用现有落球区**:各阵营色小球下落,经 `Xn` 倍率门放大数值,最终落入**攻击类型结算槽**(大球 / 小球 / 护盾 / 激光 …),把当前倍率**兑现**为对应阵营炮台的一项**火力/护盾参数**。
- **右世界(战场)= 新增四象限对战舞台**:每个阵营一座**炮台**(生命 HP + 护盾),按左侧编程好的参数**周期性发射投射球**互相攻击;投射球复用同一套物理。
- **经济桥**把左侧结算实时喂给右侧炮台参数;**大球积分→投射球更大,小球积分→投射球更多,护盾积分→炮台护盾更高**。
- **存亡联动**:炮台被打空生命/积分即**死亡**,其**左侧落球通道随之冻结**(不再吐球);**最后存活的炮台获胜**。
- 全流程**纯自动 + 确定性种子**:同种子可完整复现整局;支持**应用内直接编码导出 MP4**。

> 一句话架构:**左右各是一个落球世界,炮台是把两世界连起来的业务对象;一切参数皆指令、皆可改、皆可复现。**

## 1. 背景与产品意图

### 1.1 内容形态

对标 B 站 / YouTube 高热度的「小球对战 / 弹球大战 / marble battle」自动演化视频:开局四方势力,靠某种经济机制积累火力,互相轰击直到只剩一家,全程无人操作、一镜到底、结局随机但可复现。参考截图(双棠SaMa)即此形态:

- **左半屏**:落球盘(顶部漏斗 `x16`、中部 `x2/x4/x8` 倍率格、底部一排攻击类型槽:激光球/散弹/直射/齐射/护盾/大球/中子星/散血球),顶部四个计分盒对应四阵营,并有「散弹解封时间 1200s」「本局已进行 0s」等计时。
- **右半屏**:2×2 四象限,每格一个发光粒子团(炮台),显示阵营名(如 Caleb of Spades III / Xiaolin / Diu / Wemmbu II)、当前火力参数、积分、`20M` 生命(带护盾图标);四团互相喷射弹幕。

### 1.2 为什么复用落球区

v1.6.2 已经具备:落球物理、倍率标号、`Xn`/`RUN` 销毁函数、按颜色归属的阵营积分、公式驱动的 size/weight、SQLite 投影表、场景 JSON 快照。**这些正是"经济引擎"的现成零件**。v2.0 不重写落球,而是:

1. 把 `RUN` 泛化成一族**攻击类型结算槽**(仍是"销毁器 name = 函数"的老机制);
2. 把 `Faction` 从"只有积分"扩展成"炮台"(加生命/护盾/火力参数);
3. 新增一个**右世界**(同样是落球物理的一个实例),让炮台把参数变成弹幕;
4. 加一层**导演 + 计时线 + 录制**,让整件事自动跑成一段可导出的视频。

### 1.3 铁律沿用(架构不变量,违反=冻结区违规)

- **一切操作皆指令**:v2.0 每个新功能(布阵、开炮、解封、录制…)都必须先有指令、后有按钮;
- **控制台完备性**:关掉右侧所有面板,仅靠控制台手输指令能驱动整局对战与导出;
- **窗口关闭=隐藏**:新增的舞台/炮台/武器/录制窗口一律不销毁、状态保留;
- **运行时权威 + 文件出入口**:战场是瞬态运行时;配置(武器库/炮台/阵型/计时线)走独立 JSON,和场景快照一样"文件→运行时"单向;
- **自研物理,无第三方物理库**;
- **确定性**:固定步长 + 单一有种子 RNG,同种子同结果。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G1 | **合成舞台视图**:左落球区 + 右对战舞台 + HUD 三合一,作为主内容;编辑态与播放/录制态可切换 |
| G2 | **攻击类型结算槽**:把 `RUN` 泛化为可配置的一族结算函数(大球/小球/护盾/…),命中即把倍率兑现为阵营炮台的对应参数 |
| G3 | **炮台模型**:每阵营一座炮台,具备生命 HP、护盾 Shield、一组火力参数(投射球大小/数量/类型/射速…) |
| G4 | **右世界弹幕对战**:炮台按参数周期发射投射球(复用落球物理),命中敌方炮台先削护盾再扣血 |
| G5 | **经济桥**:左侧结算实时改写右侧炮台参数(大球→size、小球→count、护盾→shield,其余类型见 §5.6) |
| G6 | **存亡联动**:炮台生命/积分归零即死亡并从战场移除;**该阵营左侧落球通道冻结**;最后存活者胜 |
| G7 | **导演 + 计时线**:回合计时、攻击类型**按时间解封**(如"散弹 1200s 解封")、胜负判定、开/收局全自动 |
| G8 | **纯自动 + 确定性种子**:一键开跑;同种子完整复现;可保存/加载"对战剧本(种子+配置)" |
| G9 | **应用内直接编码导出 MP4**:离线逐帧渲染合成整段视频(优先 OS 原生 Media Foundation,见 §5.12/§12) |
| G10 | **尽可能大的可改动**:武器库、炮台、阵型、计时线、经济映射、配色、分辨率、帧率、时长——**全部数据/指令/表驱动,可热重载** |
| G11 | **兼容现有落球**:不破坏 v1.6.2 任一场景文件、指令、验收;老场景仍可单独当"纯落球"用 |
| G12 | **HUD 与观感**:顶部四阵营计分盒、炮台卡片(名/参数/积分/生命)、计时器、攻击类型条、创作者水印位 |

### 2.2 非目标(v2.0 划界)

- **不做联网 / 账号 / 商城 / 真实观众投票**(截图中"投票""bilibili"仅作 P2 钩子位预留,见 §9.2);
- **不引入第三方物理库**(弹幕沿用自研 `PhysicsEngine`);
- **不做完整脚本语言**:武器/导演用**声明式 JSON + 固定动词表**,不做图灵完备表达式(可扩展词表);
- **不追求真实弹道学 / 3D**:2D、圆-矩形/圆-圆足矣;
- **不做实时 4K**:分辨率/帧率可配,demo 目标见 §9.2;
- **不改 Shell 冻结区**:表窗口/停靠/指令语法一律经 App 侧包装,碰不动就上报。

## 4. 术语

| 术语 | 含义 |
|---|---|
| **舞台 / 合成视图(Stage)** | 左落球区 + 右对战舞台 + HUD 的三合一主视图;录制时逐帧渲染的就是它 |
| **左世界 / 经济世界(EconomyWorld)** | 现有落球区的 `SceneWorld` 实例;产出各阵营炮台参数 |
| **右世界 / 战场世界(BattleWorld)** | 新增的第二个 `SceneWorld` 实例;跑炮台与投射球 |
| **炮台 / 对战方(Turret / Combatant)** | 每阵营一座;有生命 HP、护盾 Shield、火力参数、象限位、存活标记;由 `Faction` 扩展而来 |
| **象限(Quadrant)** | 右世界的战位;demo 为 2×2 四格,可配 N 方(§9.2) |
| **生命 / 护盾(HP / Shield)** | 炮台耐久;来袭投射球先削护盾、护盾破再扣血;归零→死亡(截图 `20M` 即初始值) |
| **积分(Points)** | 炮台累计数值;截图中间那行数字;死亡时清零(见 §5.3 存亡规则) |
| **攻击类型结算槽(Settlement Slot)** | 左世界底部的一类"销毁器",`Name`=攻击类型名(大球/小球/护盾/…);命中即把倍率兑现给阵营炮台的对应参数 |
| **倍率门(Multiplier Gate)** | 左世界既有 `Xn` 销毁器/通道;落球途经放大倍率(沿用 v1.6) |
| **火力参数(Firepower Params)** | 炮台一组可被经济改写的数:投射球 size、count、射速、护盾、以及各攻击类型的强度 |
| **投射球(Projectile)** | 右世界里炮台发射的球;复用 `Ball`;带发射方阵营色与伤害 |
| **武器库 / 攻击类型库(Weapon Library)** | 声明式定义每种攻击类型如何把"积分"变成"弹幕行为"的参数化词表;可增删改、热重载 |
| **经济桥(Economy Bridge)** | 把左世界结算事件映射为右世界炮台参数增量的规则层 |
| **导演(Director)** | 驱动整局的自动状态机:开局→计时→解封→判定存亡→收局;唯一改变全局状态的权威 |
| **回合 / 本局(Round)** | 一整局对战;有计时、随机种子、配置快照(=剧本) |
| **解封时间线(Unlock Timeline)** | "某攻击类型在第 T 秒解封"的时刻表(截图"散弹解封 1200s") |
| **剧本(Scenario)** | 种子 + 全部配置的一份可存档快照;加载即可完整复现一局 |
| **确定性(Determinism)** | 固定步长 + 单一有种子 RNG ⇒ 同剧本逐帧一致 |
| **录制 / 编码(Record / Encode)** | 离线逐帧把舞台渲染成图像并编码为 MP4 |
| **HUD** | 顶部四阵营计分盒、炮台卡片、计时器、攻击类型条、水印位 |

| SL-02 | 结算语义:把球**当前倍率** `m` 交给**经济桥**,按该攻击类型的映射累加到球所属阵营炮台的对应参数;随后**球复位为初始倍率并瞬移回生成区**(与 `RUN` 同款传送,复用 `TeleportBall`) | P0 |
| SL-03 | `RUN` 保留并**归入结算族**的一员(等价"通用积分"结算),旧场景零改动可用(G11) | P0 |
| SL-04 | `Xn` 倍率门语义不变(先经门放大、再落结算槽,才是完整"编程"链路) | P0 |
| SL-05 | 攻击类型名**来自武器库配置**(§5.6),可增删改并热重载;`Parse` 由"硬编码 Xn/RUN"改为"Xn + 查表" | P0 |
| SL-06 | 未知 `Name`:沿用 v1.6 策略——仅传送 + Warn(Fail-safe) | P0 |
| SL-07 | 结算槽可视化:沿用销毁器"无边框方 + 居中显示 name";可选按攻击类型上色/图标(§5.10) | P1 |

### 5.6 攻击类型库(数据驱动,尽可能大可改)

> 这是"可改动性"的核心:**每种攻击类型 = 一条声明式配置**,规定"落入此槽的积分如何变成弹幕行为"。截图 8 类作为内置模板,用户可增删改、可只留几类、可造新类。

内置攻击类型(模板,均可改/可删):

| 类型名 | 经济语义(积分兑现为…) | 弹幕语义(开火表现) |
|---|---|---|
| **大球(BigBall)** | 累加到 `ProjectileSize`(球更大) | 发射体积大、伤害高、速度慢的重弹 |
| **小球(SmallBall)** | 累加到 `ProjectileCount`(球更多) | 单次多发小弹,火力密度高 |
| **护盾(Shield)** | 累加到炮台 `Shield`(不打人,防御) | 无弹幕,提升自身护盾 |
| **激光球(Laser)** | 累加"激光强度桶" | 直线穿透高速细弹/持续束(可近似为高速小球串) |
| **散弹(Shotgun)** | 累加"散弹强度桶" | 扇形一次多发、大散布角(**默认第 1200s 解封**) |
| **直射(Direct)** | 累加"直射强度桶" | 单发直线高精度,低散布 |
| **齐射(Volley)** | 累加"齐射强度桶" | 蓄力后一次性齐发一批 |
| **中子星(Neutron)** | 累加"中子星强度桶" | 高质量弹/引力弹,近域拉扯(复用重力箭头思路) |
| **散血球(BloodSplit)** | 累加"分裂强度桶" | 命中后分裂成多枚子弹(二次伤害) |

## 10. 验收标准(v2.0 可勾选草案)

1. 主内容可切到**合成舞台**:左落球区(兼容老场景)+ 右四象限战场 + HUD;三态(编辑/播放/录制)可切。
2. 落球经 `Xn` 放大后落入**攻击类型结算槽**,倍率被**兑现**为对应阵营炮台参数(大球→球更大、小球→球更多、护盾→护盾值),控制台可复现整条链路。
3. 四炮台按阵型就位,**自动开火**互轰;来袭敌色球**先削护盾再扣血**;`Hp≤0` 炮台**死亡并移除**。
4. 炮台死亡后,**其左侧该色停止落球**;存活 ≤1 时**判定胜者**(全灭平局)。
5. `battle.start seed=N` **一键跑完整局**;**同种子逐帧/事件级复现**;`散弹` 在设定秒数**解封**。
6. **武器库/炮台/阵型/经济/解封/HUD 全部可改**:改 JSON 或指令后(可热重载)行为随之变化。
7. **控制台完备**:关掉所有面板,仅手输指令可布阵→编程→开局→解封→分胜负→导出。
8. **性能**:目标逻辑分辨率下四炮台 + 上千在飞投射球播放态 ≥30FPS;弹数封顶不失控。
9. **应用内导出 MP4**:`record.start` 产出可正常播放的 H.264 MP4(编码后端为 §12 获批方案);不可用时降级 PNG 帧且有提示。
10. 版本号 **2.0.0**;**无第三方物理库**;**老场景/指令/验收零回归**;冻结区未擅改(或已上报获批);新依赖(若有)均经 §12 拍板。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| **MP4 编码引入依赖**(唯一红线) | 走 §12 上报;首选 OS 原生 MF(无包);兜底 PNG 帧不阻塞 demo |
| **P/Invoke 64 位崩溃**(MF/COM 互操作) | 严守二次开发手册血泪:结构布局逐字段核对 x64,签名默认不可信,先小 spike |
| **确定性被破坏**(随机源/浮点/多线程) | 单一有种子 RNG;固定步长;录制态离屏同步渲染;`determinism.check` 自检 |
| **性能:粒子/弹幕爆炸** | 弹数硬上限 + 对象池 + Freeze/缓存 + 必要时 WriteableBitmap;倍率/尺寸 Clamp |
| **倍率数值爆炸** | 复用 √/log 缩放与 `ClampMultiplier`;参数上限;大数 K/M/G/T 显示 |
| **误改冻结区**(表窗口/停靠/语法) | 全部 App 侧自绘/包装;碰不动即上报,不先斩后奏 |
| **老场景回归** | format5 不动;新配置独立文件;发版前复跑 v1.6 相关验收 |
| **右世界与经济世界耦合** | 两个独立 `SceneWorld` 实例 + 明确的经济桥单向接口;战场默认不投影 SQLite |
| **水印/第三方标识合规** | 默认不内置任何真实平台/个人标识;仅留用户自填占位;不冒名 |
| **观众投票(P2)引入外部输入不确定性** | v2.0 划界不做;预留钩子时也须与确定性种子隔离或显式标注"非复现段" |

## 12. 依赖与冻结区影响(必读:MP4 编码选型上报模板)

v2.0 绝大多数在 **App 自由区**(新视图、新模型、新指令、新配置、扩展 DespawnFunctions/Faction),**不需上报**。唯一需要上报确认的是 **RC-03 的 MP4 编码后端选型**,因为可能引入新依赖(二次开发手册 §3.5/§6.3:框架依赖集 {AvalonDock,.NET,SQLite} 之外的新包须用户拍板)。

代理实现到 K8 前,**必须停手**,在给用户的消息最显眼处贴出下述上报,获批再落地:

```
⚠️ 冻结区/依赖变更请求(MP4 编码后端)
- 想改什么: 为 record.* 引入 H.264 MP4 编码能力
- 为什么非改不可: 产品已拍板"应用内直接编码 MP4"(V2Q4),现有依赖集无编码器
- 候选方案:
  A. Windows Media Foundation Sink Writer(OS 原生 COM/P-Invoke,**不加 NuGet 包**)
     代价: 需写 COM 互操作,严守 x64 结构布局(手册血泪);仅 Windows
  B. 随包 ffmpeg.exe + 进程管道喂帧(不加 NuGet 包,但分发多一个可执行文件)
     代价: 需管理外部进程与二进制体积/许可
  C. 托管绑定(如 Media Foundation/FFmpeg 的 NuGet 包)
     代价: **引入新框架级依赖,须本条批准**
- 影响面: 仅 App 录制路径;不触碰场景/物理/Shell;失败可降级 PNG 帧(RC-08)
- 建议: 首选 A(最贴近"无新依赖"),B 次之;C 仅在 A/B 不可行时
- 回滚: 录制降级为 PNG 帧序列,其余功能不受影响
(等待确认;未批准前录制先走 PNG 帧兜底,其余阶段照常推进)
```

其余若出现"不动冻结区就实现不了"的点(例如必须改 Shell 表窗口才能做武器表),同样按手册 §6 上报,不得先斩后奏。
