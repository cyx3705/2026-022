> 文档性质：派生应用需求规划（**不含实现代码**）

> 基线实现：WBall **v1.4.0**（场景尺寸 / scenes 表 / 全对象旋转拉边 / OBB）

## 0. 一句话定义

**v1.5** 只做一件事：在落球区提供**线框作图器**，把用户画出的**封闭折线**一键**实体化**为可参与碰撞的方块（`block`），并为此整条工作流提供**独立的线框控制窗口**（不与现有「落球工具」面板挤在一起）。

---

## 1. 背景与目标

### 1.1 为何需要 v1.5

v1.4 已能对手动放置的轴对齐/旋转方块做精修，但关卡里常见的「斜坡、平台折线、不规则障碍轮廓」仍需一块块摆。线框路径更符合「先画轮廓、再变实体」的关卡设计习惯。

### 1.2 v1.5 目标

| 编号 | 目标 |
|---|---|
| G1 | **线框作图**：在场景内区用鼠标加点形成折线；可预览、可撤销点、可显式闭合 |
| G2 | **闭合门禁**：仅封闭线框可实体化；未闭合有明确提示，禁止静默失败 |
| G3 | **一键实体化**：封闭线框转为一个或多个 `block`，进入 SceneWorld / `scene_objects`，可用 v1.4 手势继续改 |
| G4 | **独立控制窗口**：线框工具的模式、闭合、实体化、选项集中在**新面板窗口**，与「落球工具」分离 |
| G5 | **不破坏既有不变量**：运行时权威、位置不入库、指令回显、无第三方物理库、无视频、不改 AppShell 冻结区 |

### 1.3 非目标（v1.5）

- 不做视频录制 / 导出 / 预览。
- 不做自由曲线（贝塞尔）、布尔运算、图层系统。
- 不做「线框本身参与球碰撞」（线框仅是编辑几何；碰撞只发生在实体化后的 block 上）——除非 §9 决策另开。
- 不引入第三方物理 / 几何库（剖分算法自研或极简实现）。
- 不改指令语法解析器、DockingHost、Core 契约（若必须动冻结区 → 上报）。
- 不把线框按钮塞进现有 `dropzone` 面板作为主入口（可保留极简入口链到线框窗，但**主控在新窗口**）。

## 2. 与 v1.4 的关系

```
WBall v1.4.0
  · 场景尺寸 · 界外实体 · scenes 表 · 全对象旋转/拉边 · OBB
        │
        │  v1.5 增量（本文）
        ▼
WBall v1.5
  · 线框作图器
  · 封闭线框 → block 实体化
  · 独立「线框」控制窗口
```

| v1.4 能力 | v1.5 如何复用 |
|---|---|
| 落球区画布 + 选择/移动/旋转 | 线框点在同一画布；实体化后的 block 走既有手势 |
| `scene.save/load` format 2 | 快照升 **format 3** 写入线框；兼容读 format≤2（无线框） |
| `scene_objects` / OBB | 实体化产物写入对象表；碰撞沿用 block OBB |
| 指令总线 + 面板 JSON | 新 `wire.*` 指令；新面板 `wireframe.json`（或等价 id） |
| 右侧「落球工具」 | **保留**；线框专用操作进**新窗口**，避免面板膨胀 |

## 3. 术语

| 术语 | 含义 |
|---|---|
| **线框（Wireframe）** | 已闭合并提交的折线路径；进快照与 `wireframes` 表 |
| **草图（Sketch）** | CAD 式临时绘制缓冲；加点中；未 close 前不进表、默认不落盘 |
| **顶点（Vertex）** | 草图/线框上的一个世界坐标点；仅落在场景内区 |
| **闭合（Closed）** | 草图显式/近起点闭合后，提交为线框 |
| **实体化（Solidify）** | 将已提交线框转为一个或多个 `block`；成功后删除线框与草图 |
| **线框控制窗口** | v1.5 新增的停靠控制面板，承载线框工具全部主操作 |

## 4. 功能需求

优先级：**P0** 必须 ｜ **P1** 尽量 ｜ **P2** 可后置

### 4.1 线框作图（画布）

| 编号 | 需求 | 优先级 |
|---|---|---|
| WF-01 | 进入「线框」工具后，在场景**内区**左键点击依次加点；折线实时预览 | P0 |
| WF-02 | 点击**界外实体区**不加点，并提示「超出场景」 | P0 |
| WF-03 | 进行中线框：显示顶点手柄 + 折线段；当前线段可跟鼠标橡皮筋预览（P1） | P0 / P1 |
| WF-04 | **撤销上一顶点**（快捷键建议 Backspace / Ctrl+Z 之一；面板按钮必有） | P0 |
| WF-05 | **清空当前进行中线框**（面板按钮；须确认或可一键撤销） | P0 |
| WF-06 | 顶点默认可拖改位置（选择/线框编辑态）；松手走指令回显 | P1 |
| WF-07 | 仿真播放时：建议禁止改线框（或只读显示）；与 v1.3「仿真中限制编辑」一致 | P0 |
| WF-08 | 不与放置方块工具冲突：切到 `scene.tool mode=block` 等时，进行中线框**保留在内存**（不丢），直到用户清空/实体化/切换策略见 §9 | P0 |

### 4.2 闭合

| 编号 | 需求 | 优先级 |
|---|---|---|
| CL-01 | **显式闭合**：面板 / 指令 `wire.close`；点数 ≥ 3 才允许 | P0 |
| CL-02 | **点击近起点闭合**：点击落在起点吸附半径内视为闭合（半径可配置，默认约 12 逻辑像素；**默认开启近点闭合**） | P0 |
| CL-03 | 闭合后路径标记 `closed=true`；绘制上首尾相连，填充半透明预览（可选 P1） | P0 / P1 |
| CL-04 | 已闭合后仍可「打开」再编辑（`wire.open`）——P1；P0 可仅支持删点后重画 | P1 |
| CL-05 | 自交多边形：P0 **允许绘制但实体化前校验失败并提示**；或 P1 自动拒绝闭合——见 §9 | P0（校验） |

### 4.3 实体化

| 编号 | 需求 | 优先级 |
|---|---|---|
| SF-01 | 仅 `closed=true` 可实体化；否则 Fail 并说明原因 | P0 |
| SF-02 | 实体化结果为 **≥1 个 `block`**，带稳定 id（如 `objN` 序列），写入 SceneWorld | P0 |
| SF-03 | 生成的 block **立即**可被选择 / 移动 / 旋转 / 拉边；碰撞按 v1.4 OBB | P0 |
| SF-04 | 实体化后**删除源线框**（含显示；不保留草图/表行） | P0 |
| SF-05 | 实体化算法与块粒度见 **§9 V5Q1**（实现前必须关闭决策） | P0 |
| SF-06 | 实体化全程经指令（如 `wire.solidify`）；控制台可重放 | P0 |
| SF-07 | 实体化失败（自交、面积过小、点数不足）不产生半截 block；原子失败 | P0 |

### 4.4 线框对象的存取与投影

| 编号 | 需求 | 优先级 |
|---|---|---|
| DT-01 | 线框可随 `scene.save` 写入快照（**format ≥ 3**）；`scene.load` 恢复 | P0 |
| DT-02 | 兼容：format 1/2 无线框字段 → 空列表 | P0 |
| DT-03 | 投影：独立表 `wireframes`；实体化成功后从表删除 | P0 |
| DT-04 | 表改顶点坐标须打进 SceneWorld（与 v1.3 投影纪律一致）；禁止只改库 | P0 |
| DT-05 | 线框**不**参与球碰撞；不进物理步进查询列表 | P0 |

### 4.5 独立线框控制窗口（本版 UI 焦点）

> 用户定调：**为线框作图 + 实体化整条功能添加新的控制窗口**。

| 编号 | 需求 | 优先级 |
|---|---|---|

## 5. 指令增量（草案）

语法仍遵守：**域.动作**，仅一个点。

| 指令 | 说明 | 优先级 |
|---|---|---|
| `scene.tool mode=wire` | 进入线框绘制工具（与 block/arrow/… 并列） | P0 |
| `wire.point x= y=` | 追加顶点（画布点击最终发此令） | P0 |
| `wire.undo` | 删除最后一点 | P0 |
| `wire.clear` | 清空进行中或指定 id 线框 | P0 |
| `wire.close [id=]` | 显式闭合 | P0 |
| `wire.solidify [id=] [keep=true\|false]` | 实体化；默认 keep=false | P0 |
| `wire.list` | 列出线框 id / 点数 / closed | P0 |
| `wire.select id=` | 选中某条已存线框 | P1 |
| `wire.open id=` | 打开已闭合线框继续编辑 | P1 |
| `wire.movept id= index= x= y=` | 移动顶点 | P1 |

> 命名备选：若希望全部挂在 `scene.*` 下，可用 `scene.wireadd` 这类单点名，但可读性差；**推荐独立 `wire` 域**（与 `ball` / `sim` 并列，仍在 App 自由区注册）。

画布手势 → 指令映射：

| 手势 | 指令 |
|---|---|
| 线框工具下点击内区 | `wire.point x= y=` |
| 近起点点击 | `wire.close`（或 point + 自动 close） |
| 实体化按钮 | `wire.solidify …` |

## 6. 数据与快照

### 6.1 SceneSnapshot（相对 v1.4 format 2）

建议 **format = 3**：

```json
{
  "format": 3,
  "worldWidth": 800,
  "worldHeight": 600,
  "objects": [ { "id": "obj1", "type": "block", "...": "..." } ],
  "wireframes": [
    {
      "id": "wire1",
      "closed": true,
      "points": [ { "x": 100, "y": 100 }, { "x": 200, "y": 100 }, { "x": 150, "y": 180 } ]
    }
  ],
  "balls": []
}
```

| 规则 | 说明 |
|---|---|
| 权威 | 文件 ↔ SceneWorld；库不 hydrate 场景 |
| 线框 | 只存几何与 closed；不存「进行中橡皮筋」临时态（可选：进行中不落盘，仅已提交线框落盘） |
| 兼容 | 读 format≤2：`wireframes=[]`；写默认 format 3 |

### 6.2 运行时模型（规范级）

```
SceneWorld
  ├── Objects (block/arrow/spawner/despawner)   // 既有
  ├── Wireframes[]                              // 新增
  │     id, Closed, Points[]
  ├── Balls
  └── Tool = … | Wire
```

## 7. 实体化算法（规范意图，细节待决策）

实现前必须关闭 **V5Q1**。文档层给出可选方案，便于评审：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 凸分解 → 多 block** | 简单多边形凸分解后，每块用 OBB/AABB block 近似 | 碰撞复用现有 AABB/OBB | 块多；凹形近似误差 |
| **B. 三角剖分 → 多小 block** | Ear clipping 后每三角形一个 block（或合并共边） | 实现常见、封闭即能填 | 块数量大，编辑嘈杂 |
| **C. 边框描边 → 沿边生成细长 block** | 只沿边生成有厚度的墙段，不填充内部 | 适合「管道/围墙」关卡 | 不是区域填充；与「实体化」语义偏「描边」 |
| **D. 单一多边形碰撞体** | 新增碰撞类型 poly（非 block） | 几何保真 | **超出「变成 block」**；要扩物理与手势，体量大 |

**产品定稿（V5Q1）**：**方案 A — 凸分解**（实现上：耳切三角化 → 凸片 → 每片拟合为旋转 `block`/OBB）。产物必须是 `block`。

> ⚠️ **v1.5.1 勘误**：上述「多 block / OBB 拟合」落地结果不符合产品意图（变成一堆方块）。  
> **正确语义**见专项文档：`docs/WBall_v1.5.1_异形实体化与无边框需求.md`  
> （**一个异形实体** + 内部三角拼接；绘图/实体无边框融合。）

实体化质量门槛（写入验收）：

- 闭合多边形面积 ≥ 64 px²；
- 边长过短的连续点可合并；
- 输出 block 边长 ≥ 8（与现有最小尺寸一致）；
- **自交多边形禁止实体化**（V5Q4）。

## 10. 验收标准（v1.5 可勾选草案）

1. 存在独立「线框工具」控制窗口，可显示/停靠；主流程不必依赖手输指令。
2. 线框工具下在内区加点可见折线（草图）；界外加点被拒绝。
3. 点数 ≥ 3 时可显式闭合；近起点点击可闭合；闭合后进入 `wireframes`。
4. 未闭合时实体化失败且有清晰错误信息；不产生 block。
5. 自交线框实体化失败；闭合且简单多边形实体化生成 ≥1 个 block；球可与之碰撞。
6. 实体化后源线框/草图删除（无残留描边）；block 可用 v1.4 手势编辑。
7. `scene.save` / `scene.load` 能恢复**未实体化**的已提交线框（format 3）；format 2 旧档可加载。
8. 相关操作在控制台有指令回显；可手输 `wire.*` 复现。
9. 无第三方物理库；无视频；未改 AppShell 冻结区（或已上报获批）。
10. 回归：v1.4 场景尺寸、scenes 表、旋转拉边、OBB 行为不被破坏。

## 11. 风险

| 风险 | 应对 |
|---|---|
| 实体化碎块过多，关卡难编辑 | 方案 A；短边合并；软上限提示 |
| 凹多边形 / 自交处理复杂 | 自交拒绝实体化；简单多边形凸分解 |
| 草图与线框双模型状态乱 | 工具互斥；close 才进表；solidify 原子清理 |
| 面板与画布双入口状态不一致 | 单一 SceneWorld 权威；面板只发指令 |
| 顶点列表投影难用表格编辑 | 表只作列表/元数据；细改以画布为准 |
