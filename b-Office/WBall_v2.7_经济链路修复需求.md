## 0. 问题与一句话定义

**缺陷根因**：v1.6 的销毁器语义是"命中即传送回生成器"，`Xn` 倍率门也不例外。Demo 场景 X16 门在生成器正下方 ⇒ 全部球在「生成 → X16 → 传送回生成」死循环，永远到不了底部结算槽 ⇒ 四阵营 PTS 恒 0、炮台拿不到任何子弹分配。

**v2.7** 修正落球经济为参考视频的正确链路：**先落球 → 途经 `Xn` 倍率门（穿透，数字翻倍）→ 落入底部结算槽 → 按球上数字（倍率）与颜色（阵营）给对应炮台分配子弹/护盾 → 球传送回顶部重新落**。

## 1. 功能需求

### 1.1 倍率门穿透化（P0，语义变更）

| 编号 | 需求 |
|---|---|
| GT-01 | `Xn` 销毁器改为**穿透门**：球命中即倍率 ×n，随后**推出门体下沿继续下落**（保留速度），不再传送 |
| GT-02 | 防重触发：穿透后球体置于门体下方（沿门体朝向推出），同一穿越只结算一次 |
| GT-03 | `RUN` 与攻击类型结算槽维持"结算 + 传送回生成器"语义不变（这是回环的终点） |
| GT-04 | 语义变更说明：v1.6 老场景中依赖 `Xn` 传送的用法自 v2.7 起行为改变（记录于本文档，属产品拍板） |

### 1.2 生成器落点散布（P0）

| 编号 | 需求 |
|---|---|
| SP-01 | 球传送/生成回生成器时，落点在生成器**宽度内确定性随机散布**（用世界种子 RNG），避免所有球同一列直落 |
| SP-02 | 开局吐球（SpawnEconomyBalls）同样散布 |

### 1.3 Demo 场景修正（P0）

| 编号 | 需求 |
|---|---|
| SC-01 | 底部结算槽**全宽无缝**铺满（球必落入某一槽，杜绝落在槽间隙/地板上变死球） |
| SC-02 | 槽底贴地（槽体覆盖到世界底沿），落地即结算 |
| SC-03 | 布局仍为：顶部生成器 → X16 → 两排倍率门 → 引导钉阵 → 底部六槽（大球/小球/护盾/直射/齐射/激光球） |

### 1.4 验收标准

1. `demo.play seed=42` 后 60 秒内：四阵营 **PTS 持续增长**，火力参数（子弹数量/大小/护盾）随结算变化；HUD 计分盒数字滚动。
2. 左侧肉眼可见完整循环：彩球下落 → 过门数字翻倍（球上标号变化）→ 落槽消失 → 顶部重生。
3. 无死球：任意时刻经济世界球数恒等于开局吐球数。
4. 同种子两局确定性哈希一致；构建零警告；版本 **2.7.0**。
